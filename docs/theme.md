# 主题与切换动效

本文说明主题数据来源、令牌维护要求、主题色板和切换行为。当前工作台交互见[工作台说明](workbench.md)，测试要求见[测试说明](testing.md)。

## 1. 主题机制

主题的唯一生效入口是文档根 `data-theme`。`App.vue` 将 `workspace.selectedThemeId` 同步到该属性；主题 ID 和名称定义在 `src/templates/storage/types.ts` 的 `DEFAULT_THEME_ID` 与 `THEMES` 中。

当前主题为 `Darkode`（深色，默认）、`Claucode`（浅色）和 `Hollowcode`（深色，近纯黑底和琥珀金强调色）。主题色值以 `src/app/theme.css` 为准。

每个主题块必须声明完整令牌，`:root` 中保留与 Darkode 相同的兜底值。完整性由 `tests/unit/theme-tokens.test.ts` 检查。主题块同时应用于 `[data-theme='…']` 和相同 ID 的 `[data-theme-sample='…']`。

## 2. 令牌范围

颜色令牌的名称和取值以 `src/app/theme.css` 为唯一来源；尺寸、形状、动效、层叠与字体族令牌在 `src/app/scale.css`（全局一套，不随主题变化），两边都不在组件里写字面色值。新增主题时，检查并填写下列全部颜色类别：

- 工作台底色、顶栏、面板、弹层、描边、正文、次级文字、强调色和成功色。
- 强调色文字、强调色底上文字、错误状态、错误表面和诊断位置文字。
- 悬停浮层、选中浮层、分隔线、拖动把手反馈。
- 模板卡片底与模板抽屉底、编辑器正文与工具栏底、当前行和面板分隔线。
- 预览画布、内容卡片、iframe 占位、引用文字、代码文字与背景、标题、媒体错误、折叠标题、剧透和 imagemap 热区提示。
- 编辑器标签、参数、结构符、无效标签和当前行高亮。

`--color-accent` 用于强调色图形、顶栏品牌标志和焦点状态；需要达到正文对比度的文字使用 `--color-accent-text`。`--color-success` 也作为文字使用，应达到文字对比度要求。当前 Claucode 的代码块保持深色，代码文字由 `--preview-code-text` 单独提供。

模板界面（内容族）的浮起效果不引入新色值：卡片底用 `--color-surface`、浮层底用 `--color-surface-raised`（见 `src/app/scale.css` 的 `--surface-content` 与 `--surface-overlay`），轮廓与分隔线用 `--color-border` 和 `--color-divider-strong`。因此新增主题只要填好这两档面与两条线，模板卡片在浅色主题下也会自然变成“比框架面更亮的纸面”。

浮层取色：帮助面板（仪器族）取 `--surface-content`，主题弹层与模板操作菜单（内容族浮层）取 `--surface-overlay`；详情块与输入框取 `--surface-inset`；辅助文字用 `--color-muted`，需要正文级对比度的强调文字（标签名、代码）用 `--color-accent-text`，强调色图形与焦点环才用 `--color-accent`。悬停与选中浮层只从 `--control-hover-background`、`--color-divider-strong`、`--color-selection-background` 与 `--editor-active-line`（当前行，12% 中性）四档取；诊断行的选中态用 `color-mix` 从 `--color-danger` 派生 8%，不在组件里另写新色值。

主题令牌修改后，更新本文件中受影响的现状和对比度数据，并更新主题令牌测试。主题色值不可只改组件或只改文档。

**令牌分层。** 颜色随主题走：三套主题块在 `src/app/theme.css`，每个主题必须声明完整集合，`:root` 保留与 Darkode 相同的兜底值。尺寸、形状、动效、层叠与字体族在 `src/app/scale.css`，全局只有一套，不随主题变化，也不允许写进主题块。语义别名（`--surface-*`、`--line-*`、`--ink-*`、`--state-*`）同样在 `scale.css`，取值引用 `theme.css` 的既有令牌，不新增色值。

**层叠阶梯。** 共五档：`--z-resize` 10、`--z-panel` 20、`--z-overlay` 30、`--z-tooltip` 40、`--z-splash` 100。规则一句话：面板低于所有浮层，浮层低于热区气泡，气泡低于开场。目前仍有 4 条规则用迁移期的旧值（开合把手 1、顶栏 dock 与分隔条 2、复制失败提示 5），见[路线与已知限制](roadmap.md)。

**迁移期占位 `--legacy-*`。** `scale.css` 末尾那一段是“字面量 → 令牌”的等价中转：值等于替换前的字面量，不属于设计语言；新增样式不得引用，某个占位不再有引用时连行删除。当前还有 11 个占位：圆角 2（4px、10000px，落在锁定的预览正文里）、字号 2（17px、18px）、时长 4（90 / 150 / 180 / 900ms）、层叠 3（1 / 2 / 5）。另有两个颜色令牌（`--shell-gutter-active`、`--shell-divider-background`）已不再被工作台引用，但保留声明以满足主题块完整性测试。收口未完成，见[路线与已知限制](roadmap.md)。

## 3. 主题色板

主题菜单色板显示每个主题自己的底色、正文色和强调色，不随当前主题变化。色板元素使用 `data-theme-sample`，复用对应主题块中的令牌，不在 TypeScript 中复制色值。

## 4. 主题切换动效

切换时，新主题以顶栏“主题”按钮为圆心进行圆形揭示。实现使用 View Transitions API 与 `clip-path: circle()`；圆半径覆盖到视口最远角，缓动为 `--ease`（`cubic-bezier(0.22, 1, 0.36, 1)`，定义在 `src/app/scale.css`）。

动画时长由 workspace 设置 `themeRevealDuration` 提供，单位毫秒，默认 `900`，范围 `0`–`5000`；`0` 表示立即切换。读取非法值时收敛到合法范围。

切换快照期间临时停用 CSS transition，防止截图状态停留在颜色过渡中。清理逻辑必须在成功、失败和超时路径都恢复 CSS transition；并发切换使用计数，避免过早恢复。

以下情况直接应用主题而不播放动画：浏览器不支持 View Transitions API、用户开启低动态效果、时长为 `0`，或无法读取触发按钮位置。降级只影响动画，主题必须正常切换。

## 5. 新增主题

1. 在 `src/app/theme.css` 添加包含全部**颜色**令牌的主题块（尺寸与动效令牌在 `src/app/scale.css`，不属于主题块），并同时提供 `data-theme` 与 `data-theme-sample` 选择器。
2. 在 `src/templates/storage/types.ts` 的 `THEMES` 中添加 ID、显示名称和说明；确认默认主题 ID 有效。
3. 复核工作台、预览、编辑器、色板与兜底样式，不能有其他主题的字面色残留。
4. 测量文字对比度并登记本节；更新 `tests/unit/theme-tokens.test.ts` 与主题菜单测试。
5. 更新[工作台说明](workbench.md)和[路线与已知限制](roadmap.md)。
