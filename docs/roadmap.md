# 路线与已知限制

> 本文面向接手本项目的开发者：这里集中记录**已经做完什么、还差什么、哪些是已知限制**。
> 兼容行为与差异的事实依据见[兼容性说明](compatibility.md)；测试与命令见[测试说明](testing.md)。
> 本文是本仓库现行的范围、待办与优先级来源；协作流程见[协作规则](../AGENTS.md)。
> 第一版的历史过程记录（按阶段划分的实施与验收记录）保存在本机，不随本仓库发布，因此本文用日期而非阶段编号标注结论来源。

## 1. 当前状态

- 第一版功能已实现并通过人工验收：编辑、补全、诊断、实时预览、模板与自动保存、复制、中文帮助、主题与桌面工作台布局。
- 第一版承诺的 osu! 标签覆盖 **24 / 24**；固定样例矩阵 **49 个 case**，完整性由 `node tests/check-osu-web-fixtures.mjs` 校验。
- 自动化门槛：单元与组件测试 17 个文件 / 113 个用例，Chromium 端到端 99 / 99（2026-10-11 复核）。
- 锁定基准：osu-web `61b0a41431395f86ff68fa12744f3266448ec885`，正文最大宽度 `890px`。更换基准必须经项目所有者批准并重跑全部固定样例。
- 本仓库**尚未发布在线站点**。GitHub Pages 启用前必须先设置资源路径前缀，见第 6 节。

## 2. 待项目所有者裁决的事项（未裁决前保持现状）

这些项都会影响预览的 DOM 结构或排版，需要产品决定后再改；改动时必须同步登记到[兼容性说明](compatibility.md)第 6 节的差异表、更新对应固定样例的 `metadata.json`，并重跑固定样例。

| 事项 | 现状 | 依据 |
| --- | --- | --- |
| 列表标题结构 | 上游把 `[list]` 后紧跟的首行文本包成独立的无符号列表元素；本项目把标题文本直接放在列表内部 | [兼容性说明 §6.3](compatibility.md#63-待决的列表结构差异尚未裁决2026-09-25-记录) |
| 无序列表元素类型 | 上游输出有序列表元素并附加类名后用样式改成圆点；本项目输出语义化的无序列表元素（视觉一致，元素类型不同） | 同上 |
| 块级外边距方案 | 上游块级元素上外边距为 `0`、下外边距来自其默认样式；本项目当前是上下各 `16px`、列表与段落 `12px` | [兼容性说明 §6.4](compatibility.md#64-预览配色裁决与块级外边距待决项2026-09-25) |
| 折叠盒标题高度 | 当前标题 `min-height: 24px`，上游没有该属性 | 同上 |
| 候选菜单阴影 | 菜单阴影的界面边界复核仍留作审计项 | 同上 |
| 诊断定位口径 | 现有需求条款要求「行列定位并标记」，早期实施口径写的是「仅到行末尾」；两者冲突，未改实现 | 本文第 8 节 |

**配色是硬约束**：配色按主题块组织，当前提供 `Darkode`（深色，默认）与 `Claucode`（浅色）两套。任何新增颜色、改动色值或调整透明度，都必须先取得项目所有者授权；未获授权时保持现状。令牌清单与新增主题步骤见[主题与切换动效](theme.md)，裁决记录见[兼容性说明 §6.4](compatibility.md#64-预览配色裁决与块级外边距待决项2026-09-25)。

## 3. 待所有者提供的内容

- **正式默认示例**：首次访问时写入编辑器的示例正文目前仍是开发期的临时内容（含两个外链图床地址与一个示意用的 YouTube 视频 ID）。正式内容确认后替换，替换时**不得覆盖用户已存在的本地模板**，并同步更新相关验收与固定样例。

## 4. 已知限制（保留现状，不作为缺陷处理）

| 限制 | 说明 |
| --- | --- |
| 移动端不可用 | 第一版只承诺桌面工作台；窄屏下的模板抽屉、`lastMobileView` 字段等实现是后续版本的基础，**不是第一版承诺** |
| 模板只存在本机 | 数据在浏览器 IndexedDB 中；清站点数据、无痕窗口或换设备都会丢失，且没有导出/导入 |
| Windows 剪贴板行为 | 系统可能规范化换行符；复制结果与编辑器原文的一致性以编辑器内原文为准 |
| 关闭页面瞬间的写入 | 关闭标签页时触发的异步 IndexedDB 写入不保证完成，最后几秒的修改可能丢失 |
| 构建体积 | 生产构建主脚本约 `527.68 kB`（gzip 约 `178.47 kB`），会触发超过 500 kB 的提示；尚未拆分 |
| 图片尺寸 | 上游显示阶段由服务端预取图片宽高；本项目只能由浏览器在加载后按原始宽高比与 `max-width: 100%` 缩放 |
| 无自动化跨浏览器矩阵 | 目前只在 Chromium 上跑端到端测试，其他浏览器靠人工验收 |

## 5. 发布后计划（按用户反馈排期）

- WebKit 与完整的自动跨浏览器矩阵。
- axe 自动化无障碍检查。
- 桌面宽屏与窄屏的视觉截图基线。
- 主题设置界面：圆揭示动画时长已落数据层（`themeRevealDuration`，默认 900 毫秒、可在 0～5000 之间取值），调整入口待做。
- 代表性长文档的输入响应、预览防抖与存储写入次数测量；评估主脚本的体积与拆分。
- 浏览器级失败路径注入：IndexedDB 不可用、剪贴板被拒绝、媒体加载失败、渲染异常。
- 候选菜单、帮助面板、模板菜单与弹窗的可操作性复查。
- 真实媒体（图床、音频、YouTube）在目标浏览器上的发布前人工验收。

## 6. 发布前必须完成的具体改动

- **资源路径前缀**：GitHub Pages 以项目页形式发布时，站点地址带仓库名，必须在 `vite.config.ts` 设置 `base: '/Sinka-osu-bbcode-editor-Sinkode/'`；同时把 `playwright.preview.config.ts` 的 `baseURL` 与 `webServer.url` 改到同一前缀，否则生产构建产物在线上会白屏。
- 增加 Pages 部署工作流（`REL-05`），第三方 action 一律固定到完整提交 SHA。
- 在真实浏览器上完成隐私、许可证与内容安全策略检查，并把上线命令与实际结果补入[部署说明](deployment.md)。
- 用正式默认示例替换临时示例，并重跑六条固定命令与人工验收清单。

## 7. 后续版本范围（移动端）

移动端交互整体推迟到后续版本，需求条目保留为后续版本的验收项：移动端编辑/预览切换、首次进入的默认视图、切换后单一滚动容器、模板抽屉、抽屉焦点恢复、触屏补全与触控尺寸、帮助与模板在目标设备上的滚动/焦点/无障碍验收。

**恢复条件**：重新确认移动端布局方案、断点、触控尺寸、焦点与滚动规则，并补齐移动浏览器矩阵、真实设备烟测、截图基线与无障碍证据。仓库中已有的窄屏实现与测试记录可以作为起点，但不构成发布承诺。
