# 路线与已知限制

> 本文记录当前项目范围、未完成事项和已知限制。
> 兼容行为与差异的事实依据见[兼容性说明](compatibility.md)；测试与命令见[测试说明](testing.md)。
> 当前协作规则见[协作规则](../AGENTS.md)。

## 1. 当前状态

- 当前功能范围包括编辑、补全、诊断、实时预览、模板与自动保存、复制、中文帮助、主题和桌面工作台布局。
- 第一版承诺的 osu! 标签覆盖 **24 / 24**；固定样例矩阵 **49 个 case**，完整性由 `node tests/check-osu-web-fixtures.mjs` 校验。
- 测试命令和完整的验证顺序见[测试说明](testing.md)。
- 锁定基准：osu-web `61b0a41431395f86ff68fa12744f3266448ec885`，正文最大宽度 `890px`。更换基准必须经项目所有者批准并重跑全部固定样例。
- 本仓库**尚未发布在线站点**。GitHub Pages 启用前必须先设置资源路径前缀，见第 6 节。

## 2. 待项目所有者裁决的事项（未裁决前保持现状）

这些项都会影响预览的 DOM 结构或排版，需要产品决定后再改；改动时必须同步登记到[兼容性说明](compatibility.md)第 6 节的差异表、更新对应固定样例的 `metadata.json`，并重跑固定样例。

| 事项 | 现状 | 依据 |
| --- | --- | --- |
| 列表标题结构 | 上游把 `[list]` 后紧跟的首行文本包成独立的无符号列表元素；本项目把标题文本直接放在列表内部 | [兼容性说明 §6.3](compatibility.md#63-列表结构待决项) |
| 无序列表元素类型 | 上游输出有序列表元素并附加类名后用样式改成圆点；本项目输出语义化的无序列表元素（视觉一致，元素类型不同） | 同上 |
| 块级外边距方案 | 上游块级元素上外边距为 `0`、下外边距来自其默认样式；本项目当前是上下各 `16px`、列表与段落 `12px` | [兼容性说明 §6.4](compatibility.md#64-预览外观规则与待决项) |
| 折叠盒标题高度 | 当前标题 `min-height: 24px`，上游没有该属性 | 同上 |
| 候选菜单阴影 | 菜单阴影的界面边界复核仍留作审计项 | 同上 |

主题取值和令牌清单见[主题与切换动效](theme.md)，兼容差异见[兼容性说明 §6.4](compatibility.md#64-预览外观规则与待决项)。

## 3. 待所有者提供的内容

- **默认示例内容**：首次访问时显示的默认 BBCode 示例仍待确定正式内容，当前含两个外链图片地址和一个示意用的 YouTube 视频 ID。替换时**不得覆盖用户已存在的本地模板**，并同步更新相关验收与固定样例。
- **发布授权**：把仓库转为公开、启用 GitHub Pages 都需要项目所有者明确批准后执行。

## 4. 已知限制（保留现状，不作为缺陷处理）

| 限制 | 说明 |
| --- | --- |
| 移动端支持 | 第一版只承诺桌面工作台；窄屏模板抽屉和 `lastMobileView` 字段不构成移动端支持承诺 |
| 模板只存在本机 | 数据在浏览器 IndexedDB 中；清站点数据、无痕窗口或换设备都会丢失，且没有导出/导入 |
| Windows 剪贴板行为 | 系统可能规范化换行符；复制结果与编辑器原文的一致性以编辑器内原文为准 |
| 关闭页面瞬间的写入 | 关闭标签页时触发的异步 IndexedDB 写入不保证完成，最后几秒的修改可能丢失 |
| 构建体积 | 生产构建主脚本约 `529.36 kB`（gzip 约 `179.05 kB`），会触发超过 500 kB 的提示；尚未拆分 |
| 图片尺寸 | 上游显示阶段由服务端预取图片宽高；本项目只能由浏览器在加载后按原始宽高比与 `max-width: 100%` 缩放 |
| 无自动化跨浏览器矩阵 | 目前只在 Chromium 上跑端到端测试，其他浏览器靠人工验收 |

## 5. 后续计划

- WebKit 与完整的自动跨浏览器矩阵。
- axe 自动化无障碍检查。
- 桌面宽屏与窄屏的视觉截图基线。
- 主题设置界面：圆揭示动画时长已落数据层（`themeRevealDuration`，默认 900 毫秒、可在 0～5000 之间取值），调整入口待做。
- 代表性长文档的输入响应、预览防抖与存储写入次数测量；评估主脚本的体积与拆分。
- 浏览器级失败路径注入：IndexedDB 不可用、剪贴板被拒绝、媒体加载失败、渲染异常。
- 候选菜单、帮助面板、模板菜单与弹窗的可操作性复查。
- 真实媒体（图床、音频、YouTube）在目标浏览器上的发布前人工验收。

## 6. 发布前必须完成的具体改动

- **资源路径前缀**：GitHub Pages 以项目页形式发布时，站点地址带仓库名，必须在 `vite.config.ts` 设置 `base: '/Sinka-osu-bbcode-editor-Sinkode/'`；同时把 `playwright.preview.config.ts` 的 `baseURL` 与 `webServer.url` 改到同一前缀，否则生产构建产物在线上会白屏。
- 增加 GitHub Pages 部署工作流；第三方 action 固定到完整提交 SHA。
- 在真实浏览器上完成隐私、许可证与内容安全策略检查，并把上线命令与实际结果补入[部署说明](deployment.md)。
- 确认正式默认示例内容后替换当前示例，并重跑六条固定命令与人工验收清单。
