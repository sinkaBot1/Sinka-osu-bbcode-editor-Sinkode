# UI 图标系统

> 文档状态：现行图标规范（2026-10-02），已随第一版验收；2026-10-03 补充第 8 节"工作台悬停与状态色"。实际接入状态见 §6。
> 适用范围：工作台 UI、编辑器工具栏、移动端导航、状态反馈和弹窗控件

## 1. 设计决定

第一版工作台 UI 采用 Lucide 的线性 SVG 图标作为快捷操作图标系统。图标用于提高工具栏和窄屏导航的识别速度，不能替代必要的文字说明、键盘操作或屏幕阅读器标签。

图标只服务于产品自己的工作台界面，不用于复制 osu-web 或 MOBE 的图标、样式和素材，也不改变预览区域的配色和视觉规则。

## 2. 来源与依赖

- npm 包：`@lucide/vue`
- 当前锁定版本：`1.41.0`
- 源码仓库：[lucide-icons/lucide](https://github.com/lucide-icons/lucide)，Vue 包位于 `packages/vue`
- 官方网站：[lucide.dev](https://lucide.dev)
- 包许可证：ISC
- 项目依赖记录：`package.json`、`package-lock.json`

图标通过 Vue 组件打包为本地 SVG，不在运行时从网络加载图片。新增或升级图标依赖必须继续使用 npm、HTTPS registry 和提交的 lockfile，并经过依赖变更审查。

## 4. 使用规则

### 4.1 视觉规则

- 采用单一线性图标风格，不混用 emoji、位图图标或其他图标库。
- 产品 UI 中默认尺寸为 `18px`–`20px`；触控按钮本身至少保留 `44px × 44px` 的可操作区域。
- 图标描边使用统一的 `stroke-width`，颜色读取主题令牌，不在组件中写入新的硬编码颜色。
- 图标只表达操作或状态，不使用装饰性插画填充工作区。
- 颜色不能作为唯一状态依据；错误、成功和保存状态同时提供文字或可读标签。

### 4.2 文字与标签规则

- 高频编辑操作可以使用图标按钮。
- 模板栏的新建、重命名和复制操作使用图标按钮；删除和恢复默认示例同时保留中文文字，避免重要操作只依赖图标。
- “颜色”“居中”“帮助”“主题”等容易产生歧义的功能，桌面端优先使用图标加文字，移动端使用图标加可见提示或分段控件。
- 每个图标按钮必须提供 `aria-label` 和 `title`；SVG 本身设置 `aria-hidden="true"`。
- 删除、恢复、确认等重要或有破坏性的操作必须保留文字，不允许只显示图标。

示例：

```vue
<button class="icon-button" type="button" aria-label="撤销" title="撤销">
  <Undo2 :size="18" aria-hidden="true" />
</button>
```

### 4.3 交互规则

- 图标按钮必须支持鼠标、键盘和触屏操作。
- `Tab` 焦点顺序应与界面阅读顺序一致，并保持可见焦点环。
- 弹窗、抽屉和帮助面板中的关闭图标必须支持 `Esc`。
- 拖动分隔线必须同时提供方向键调整方式，不能只依赖拖动图标。
- 悬停提示不能是唯一说明方式；触屏设备没有 hover 时，功能仍必须可理解和可操作。

## 5. 不在本决定范围内的内容

- Lucide 图标系统不负责生成产品 Logo、营销插画、背景纹理或用户卡片素材；顶栏品牌标志使用项目所有者提供的独立素材，见 §6.2。
- 不下载或复制 osu-web、MOBE 的图片、字体、图标和样式文件。
- 不使用远程图片 URL 作为工作台图标来源。
- 不为了使用图标库而修改 BBCode 解析、诊断、预览兼容规则。
- 品牌标志不属于 Lucide 图标系统：项目自有品牌素材见 §6.2，GitHub 官方标志见 §7.1，两者都按各自来源的原始形态使用。
- 不把图标系统扩展为第二套主题配色；主题颜色仍遵守[兼容性说明 §6.4](compatibility.md#64-预览配色裁决与块级外边距待决项2026-09-25)的所有者授权规则。

### 7.4 顶栏动作区的无框约定（2026-10-03 所有者裁定）

- 顶栏三个入口（GitHub 仓库、帮助、主题）统一为无框样式：静止时没有边框、没有底色，只有图形和文字；悬停浮出一层 `rgb(215 222 232 / 9%)` 中性浮层，过渡 `120ms ease`。这与编辑器工具栏按钮、模板行使用同一种语言。
- 裁定理由（含实测）：原实心底与头栏底对比度只有 `1.03:1`、1px 边框 `1.44:1`，这个"框"在视觉上几乎不成立，却把顶栏切成三个方块；去掉后同时消除了 §4.1 之外的一处低对比描边。
- 无框不等于降低可操作性：可操作区域仍是 `44px × 44px` 起（实测图标入口 44×44、文字入口 60×44），键盘焦点仍是 2px 主题色焦点环，窄屏仍整组换行且不溢出。
- `prefers-reduced-motion: reduce` 下该过渡缩短到 `0.01ms`，与顶栏开合动效一致。
- 悬停浮层与键盘焦点环都带 `border-radius: 5px`，与编辑器工具栏按钮同一半径；三个入口的内边距统一为 4px，同一组浮层外扩一致（2026-10-03 补充）。
- 动作区最左侧有一根功能休止符：`1px × 26px`、`rgb(215 222 232 / 16%)`，纯装饰、`aria-hidden="true"`、不参与 Tab 顺序。规格取自编辑器工具栏分隔线（同为 1px 宽、26px 高，不随 44px 可操作区拉满）；颜色比工具栏用的 `--color-border` 略强，因为头栏底比工具栏底亮，需要更大的分离度才能保持同级可见度（实测约 `1.5:1`，与中线两侧共同构成约 `3:1` 的边界）。它是本节的记录例外：不新增颜色令牌，也不因此改成强调色。

## 8. 工作台悬停与状态色（2026-10-03 所有者要求）

> 来源：项目所有者指出"悬停交互多会显示蓝框"，要求换成符合项目风格的样式。
> 本节把 §7.4 的顶栏口径提升为**整个工作台**的统一约定；键盘焦点环不在本次范围内，维持 2px 主题色实线。

### 8.1 两条规则

1. **悬停不改描边颜色**。控件在静止时的 1px 描边是 `--color-border`，悬停后保持不变；反馈只来自背景浮层。对照组是 §7.4 记录的实测：原来的 1px 描边在深色底上只有 `1.40:1`，一悬停就换成主题蓝 `#62b5ff`（对底色 `7.10:1`）——这个"框"本身几乎不成立，却把每个按钮都点成一个蓝色方块。
2. **强调色只表示"选中 / 活动"与键盘焦点**。浅蓝底 + 2px 左条 = 当前项；`.help-panel-filter.is-active` 的蓝描边 = 当前分类；输入框获得焦点时的蓝描边 = 活动输入位。这层含义之外，悬停不再使用强调色，因此"蓝"在工作台里只剩这三种用途。

### 8.2 悬停背景取值（不新增色值）

新增语义令牌 `--control-hover-background: rgb(215 222 232 / 9%)`，值就是顶栏、编辑器工具栏、模板行早已在用的那个中性浮层。各区域**原有的**中性浮层透明度保留原值，不统一改写：

| 位置 | 悬停背景 | 悬停时的描边 |
| --- | --- | --- |
| 顶栏动作入口、顶栏开合、编辑器工具栏按钮（§7.4 原有） | `rgb(215 222 232 / 9%)` | 不渲染描边 |

## 9. 复制按钮并入统一悬停语言（2026-10-04 所有者裁定）

> 来源：项目所有者提问"当前复制 BBCode 按钮有没有更优雅美观的设计方法"，在四种写法对比后选定"无框 + 图标 + 就地反馈"方案，并要求同时处理顺带测出的浅色主题对比度问题。
> 本节把编辑器面板头部的「复制 BBCode」从 §8.2 的"原有实心底"一档移出，纳入 §7.4 / §8 的统一口径。

### 9.1 改动前的实测问题

| 检查项 | Darkode | Claucode | 判据 | 结论 |
| --- | --- | --- | --- | --- |
| 按钮 1px 描边 vs 面板头底（`#353c47` / `#d5cab8` on `#20242b` / `#faf9f5`） | 1.40:1 | 1.54:1 | 图形元素 ≥3:1 | 两套主题下那个"框"都几乎不可见 |
| 按钮实心底 vs 面板头底（`#20242b` / `#faf9f5` 对同值） | 1.00:1 | 1.00:1 | — | 实心底与所在栏底完全相同，等于没有 |
| 成功提示浮窗文字（`--color-background` on `--color-accent`） | 7.87:1 | **2.89:1** | 正文 ≥4.5:1 | 浅色主题下不达标 |

这与 §7.4 记录的顶栏问题同源：1px 描边在深色底上对比度不足，却把面板头点成一个孤立方块。差别是顶栏在 2026-10-03 已改，这个按钮当时留在原位。

### 9.2 改动内容

1. **静止**：不描边、不铺底；`Copy` 图标 16px + 文字 13px，颜色 `--color-muted`。
2. **悬停**：`--control-hover-background`（9% 中性浮层）+ 文字转 `--color-text`，过渡 `120ms ease`，与顶栏动作区、编辑器工具栏、模板行同一套语言。
3. **按下**：改用 `--color-divider-strong` 中性浮层，文字色不变。**不照搬工具栏的"强调色实心底"**——该组合在浅色主题下只有 3.28:1（见 §9.3）。
4. **成功反馈就地显示**：图标换 `Check`、文字换「已复制」、颜色 `--color-success`，约 2 秒后还原；不再弹出浮窗。两条文案常驻 DOM 叠在同一格（`display: inline-grid` + `grid-area: 1 / 1`），按钮宽度由较长的一条决定，切换时不产生位移。
5. **失败反馈保留浮窗**：原因文字放不进按钮，仍由 `.copy-toast` 承载，配色沿用 `--color-danger-surface(-text)`；时长与改造前一致（约 2 秒）。
6. **可访问性**：可访问名称固定为「复制 BBCode」（`aria-label`，e2e 与帮助文案都依赖它）；按钮内的图标与文案 `aria-hidden`，避免名称重复；状态变化由常驻的 `.visually-hidden[role=status]` 播报——动态插入的 live region 常常不被播报，所以节点常驻、只换文字。
7. **触控目标**：视觉高度 32px，热区用 `::after` 负 `inset`（`-6px -4px`）外扩到 44px。`.panel-header` 的 `min-height` 同步由 42px 提到 44px——否则热区只在样式上成立，实际可点范围仍被容器截断在 42px（窄屏本来就被 44×44 的移动端模板入口撑到 44px，桌面端 42px 才是特例）。
8. **圆角**：3px → 5px，与顶栏动作区、编辑器工具栏的浮层半径一致。
9. **不新增任何颜色令牌**：全部取值来自既有令牌。

### 9.3 改动后的实测对比度

| 状态 | 色对 | Darkode | Claucode |
| --- | --- | --- | --- |
| 静止文字 | `#8e9aaa` / `#6c6a64` on 面板头底 | 5.45:1 | 5.13:1 |
| 悬停文字 | `--color-text` on 9% 中性浮层合成底 | 11.50:1 | 17.50:1 |
| 按下文字 | `--color-text` on `--color-divider-strong` 合成底 | 7.48:1 | 12.44:1 |
| 已复制文字 | `#78d6a3` / `#357a44` on 面板头底 | 8.86:1 | 4.96:1 |
| 失败提示 | `#ffe6e0` on `#703a30` ／ `#8f2f2f` on `#f7e4e0` | 7.55:1 | 6.55:1 |

全部 ≥4.5:1。上表按 WCAG 2.1 相对亮度公式计算（`(L1+0.05)/(L2+0.05)`，通道先做 sRGB 线性化），输入色值全部照抄[主题样式表](../src/app/theme.css)的主题块，可脱离本项目独立复算。作为交叉验证：同一公式对"珊瑚色本体 `#cc785c` 对 `#faf9f5`"算出 3.11:1，与[主题与切换动效](theme.md)记录的历史测量值逐位一致。

对照：被否决的"强调色实心按钮"在 Claucode 下白字压珊瑚底只有 3.28:1，同一主题的工具栏按下态（`--color-background` 文字）更低到 2.89:1——这也是本次不照搬工具栏按下态的原因。

### 9.4 验收依据

- [模板端到端测试](../tests/e2e/templates.spec.ts) 的「复制按钮并入工作台悬停语言，成功就地反馈、失败保留浮窗」逐项断言：静止无描边且底色透明、文字为 `rgb(142, 154, 170)`、触控热区 ≥44px（计算样式与 `elementFromPoint` 行为两层证据）、悬停为 `rgba(215, 222, 232, 0.09)` 且文字转 `rgb(215, 222, 232)`、成功就地换勾与文案且 `.copy-toast` 数量为 0、约 2 秒后自动还原、失败态浮窗仍在并贴合按钮右缘。
- 同一文件的「工作台悬停只用中性浮层」继续把 `.copy-button` 纳入 16 项控件清单。
- 「复制结果与编辑器原文逐字节一致」改为断言按钮就地反馈，逐字节一致性断言不变。
- [复制按钮单元测试](../tests/unit/templates-ui.test.ts) 覆盖逐字节复制、就地反馈与 2 秒还原、失败与缺少剪贴板两条路径、常驻播报区文案。

### 9.5 明确不在本次范围内

- **编辑器工具栏的按下态**仍是"强调色实心底 + `--color-background` 文字"，该组合在浅色主题下只有 2.89:1。它是既有实现、不属于复制按钮，本次未改，已单独记录待裁决。
- **帮助面板的复制示例按钮**仍是 `--color-surface-raised` 实心底，保持 §8.2 原状；它位于浮层内、所在底与按钮底不同色，不存在本节 §9.1 的"实心底与栏底同色"问题。
- 窄屏"只留图标"的形态本次未实现：`.panel-header` 在窄屏仍显示图标加文字，空间不足时由 `.panel-title` 的省略号让位。

## 10. 复制按钮的动效接入（2026-10-05 所有者裁定）

> 来源：项目所有者要求"给现在的复制 BBCode 按钮点击后添加更多动画"，在六个可运行方案（基线 / 就地生长 / 底色参与 / 扩散环 / 按下回弹 + 微旋 / 显式透明度地基）对比后**选定 E：按下回弹 + 对勾微旋**。
> 对比所用的可运行演示与逐帧冻结截图是开发过程产物，不随本仓库发布。

### 10.1 选定内容

| 位置 | 动效 | 时长与曲线 |
| --- | --- | --- |
| 整个按钮 | 按下缩到 `scale(0.97)`，松手回到 `1` | 90ms，工作台曲线 |
| `Check` 对勾 | 从 `scale(0.6) rotate(-24deg)` 弹出到 `scale(1) rotate(0)` | 进入 260ms，工作台曲线 |
| `Copy` 图标 | 淡出并缩到 `scale(0.85)` | 退出 180ms，工作台曲线 |
| 「已复制」 | 从下方 `2px` 浮起并淡入 | 进入 260ms，工作台曲线 |
| 「复制 BBCode」 | 上移 `2px` 并淡出 | 退出 180ms，工作台曲线 |

- 曲线与两组时长取自[工作台说明](workbench.md#动效与持续维护)的统一口径，没有新造时长或曲线。
- **不新增任何颜色令牌**，也不改动任何既有色值与透明度：全部动效只使用 `transform` 与 `opacity`，颜色仍是 §9.3 实测的那几组取值。
- 只动 `transform` / `opacity`，不触发排版；按钮宽度仍由两条文案中较长的一条决定，累计位移为 0。

### 10.2 实现约束（与 §9 的差别）

1. **图标不能再靠 `v-if` 换 DOM**。原实现里非活动的那条根本不在渲染树中，没有可动画对象。现在 `Copy` 与 `Check` 两条**常驻 DOM、叠在同一格**（`display: inline-grid` + `grid-area: 1 / 1`），与两条文案同一手法；显隐由 `.copy-button.is-copied` 状态类驱动。
2. **状态规则必须写在静止规则之后**。两处选择器同特异性时，后写的那条胜出；开发过程中正是因为顺序颠倒，出现过"对勾与原文案同时可见"的重叠。
3. **渐出时长取当前可见那条的 `transition`**。CSS 过渡读取目标状态的声明；若把 `transition` 简写写在静止态，渐出会误取 260ms 而不是 180ms。现在每条 `transition` 都写在使用它的那条规则里。
4. **按下回弹只作用在按钮本体**，不叠加到图标或文案上；触控热区仍由 `::after` 的负 `inset` 提供，缩放只改变绘制，不改变热区。
5. **低动态效果**：`prefers-reduced-motion: reduce` 下全部过渡缩短到 `0.01ms`、按下不再缩放；反馈仍然出现、只是不再运动，与顶栏、帮助面板既有口径一致。

### 10.3 验收依据

- [模板端到端测试](../tests/e2e/templates.spec.ts) 的「复制按钮成功时就地反馈，渐出用退出时长」锁定：静止态对勾透明且缩到 `0.6`；成功后对勾进入过渡为 `0.26s`、文字色终值为 `rgb(120, 214, 163)`；按下时按钮 `transform` 不是 `none`、松手回到 `none`；低动态效果下对勾与文案的过渡时长均为 `1e-05s`。
- [复制按钮单元测试](../tests/unit/templates-ui.test.ts) 锁定：两条图标与两条文案始终常驻 DOM（各 2 个），状态切换只改 `.is-copied`，可访问名称与常驻播报区文案不变。
- 人工确认要点：连续快速点击时动画必须能被打断并停在正确终态；对勾旋转与文案浮动过程中，按钮宽度和文字基线不移动。

### 10.4 明确不在本次范围内

- **不加成功色扩散环或底色泛色**：对比中的"底色参与"需要新增一个 `--color-success` 透明度取值；"扩散环"的静态形态与 2px 焦点环过于接近，会被误读成键盘焦点。两者均被否决。
- **不改 2 秒反馈时长**与失败浮窗形态，仍按 §9 与[工作台说明](workbench.md)的口径。
- **不动其他控件的动效**：编辑器工具栏、帮助面板复制按钮保持现状。
